Docs That Match

An operator following these documents today sets an API key and a per-tool throttle that no longer exist — this contract makes what the documents and comments say what the server does, and checks it on every build.

Direction

After this contract, what the documents and code comments say is what the server does - bearer tokens, a policy per provider, the frame's checks, limits held in Redis - and a repository test fails whenever a document names a setting the server would refuse, a retired mechanism, or a link to nothing. The bet is that documentation stays true only where its checkable claims are checked on every build; the rest is prose a reader must be able to trust, and is verified by reading.

The bearing. If it and the tiers disagree, the bearing wins.

Tier 1 — who it is for

Who: a team adopting the template, an organisation's platform team configuring it, a security
reviewer, and anyone reading the code.
What they want: to run, configure, extend and judge the server from its documentation,
without reading its source.
Success: every setting the documents say to set is one the server reads; adding a provider as
documented works first time; the diagrams show components that exist.
Cost today: the documents describe .NET 8, an API key (removed in Phase 1, now refused), a
per-tool throttle (retired, now refused), a startup health probe (replaced) and adding
providers by scanning (now serves nothing); several comments give advice that fails at startup.
